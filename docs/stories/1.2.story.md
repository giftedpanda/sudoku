# Story 1.2: Data Types and Board Utilities

## Status
Draft

## Story
**As a** developer,
**I want** well-defined TypeScript types and board utility functions,
**so that** all game logic has a consistent, type-safe foundation to build on.

## Acceptance Criteria
1. All game types are defined in `src/types/index.ts` matching the architecture spec
2. `createEmptyBoard()` returns a 9x9 board of empty cells with correct defaults
3. `getRowPeers()`, `getColPeers()`, `getBoxPeers()`, `getAllPeers()` return correct positions
4. `getBoxIndex()` returns the correct 3x3 box index (0-8) for any position
5. `hasConflict()` correctly detects row/column/box conflicts
6. `validateBoard()` returns a board with all `isError` flags set correctly
7. `isBoardComplete()` correctly compares a board against its solution
8. `cloneBoard()` produces a deep copy (modifying clone does not affect original)
9. Game constants (difficulty ranges, grid size) are defined in `src/config/constants.ts`
10. All utility functions have comprehensive unit tests with 90%+ coverage

## Tasks / Subtasks
- [ ] Define all types in `src/types/index.ts` (CellValue, Cell, Position, Board, Difficulty, GameState, UndoAction, SavedGame, SerializedCell)
- [ ] Define constants in `src/config/constants.ts` (GRID_SIZE, BOX_SIZE, DIFFICULTY_RANGES, etc.)
- [ ] Implement `createEmptyBoard()` in `src/lib/board-utils.ts`

- [ ] Run full test suite
- [ ] Self-verify with Definition of Done

## Dev Notes

### Architecture Context
These types and utilities are used by every other module: the generator, solver, state management, and UI components. This is the shared vocabulary of the entire application.

`Cell.notes` uses `Set<number>` in runtime but serializes to `number[]` for localStorage (see `SerializedCell`).

### File Locations
| Purpose | Path |
|---------|------|
| Type definitions | `src/types/index.ts` |
| Board utilities | `src/lib/board-utils.ts` |
| Board utility tests | `src/lib/board-utils.test.ts` |
| Constants | `src/config/constants.ts` |

### Key Patterns to Follow

```typescript
// Types — use type aliases for primitives, interfaces for objects
export type CellValue = 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | null;
export type Difficulty = 'easy' | 'medium' | 'hard';
export type Board = Cell[][];

// Constants
export const GRID_SIZE = 9;
export const BOX_SIZE = 3;
export const DIFFICULTY_RANGES: Record<Difficulty, { min: number; max: number }> = {
  easy: { min: 36, max: 40 },
  medium: { min: 30, max: 35 },
  hard: { min: 24, max: 29 },
};

// Utility functions are pure — no side effects, easy to test
export function createEmptyBoard(): Board { ... }
export function cloneBoard(board: Board): Board { ... }
```
