# Story 2.5: Error Highlighting

## Status
Draft

## Story
**As a** player,
**I want** to see cells highlighted in red when they conflict with another cell in the same row, column, or box,
**so that** I can identify and correct mistakes immediately.

## Acceptance Criteria
1. Cells with conflicting values (same value in same row/col/box) display with a red/error style
2. All conflicting cells in a conflict group are marked (not just the duplicate)
3. Error highlighting updates in real-time as values are entered or erased
4. Given cells that conflict with user input are also marked as errors
5. Error state is stored on each cell (`isError` flag) and managed by the reducer
6. When a conflict is resolved (value changed or erased), error styling is removed
7. Component tests verify error display

## Dev Notes

### Architecture Context
Error detection is already built into the architecture:
- `hasConflict(board, pos)` checks if a cell conflicts with any peer (from Story 1.2)
- `validateBoard(board)` iterates all cells and sets `isError` on each (from Story 1.2)
- The reducer already calls `validateBoard()` after `SET_VALUE` and `ERASE_CELL` (from Story 2.2/2.3)

This story mainly focuses on the **visual** presentation of errors in `SudokuCell` and verifying the end-to-end flow works correctly.

Error styling should be distinct but not overwhelming:
- Error cell: red text color (`text-red-600`), light red background (`bg-red-50`)
- Given cells with errors: same error styling (the conflict is the user's fault, but both cells are flagged)
