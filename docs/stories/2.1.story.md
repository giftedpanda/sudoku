# Story 2.1: Cell Selection and Highlighting

## Status
Draft

## Story
**As a** player,
**I want** to click a cell and see it highlighted along with its row, column, and box peers,
**so that** I can clearly see which cell I'm editing and its related cells.

## Acceptance Criteria
1. Clicking a cell selects it with a distinct visual indicator (e.g., blue background)
2. All cells in the same row, column, and 3x3 box are highlighted with a lighter shade
3. All cells with the same value as the selected cell are highlighted with a matching-number style
4. Clicking a different cell moves the selection
5. Only one cell can be selected at a time
6. The selection state is managed in the game reducer (`SELECT_CELL` action)
7. Component tests verify highlighting behavior

## Dev Notes

### Architecture Context
This story introduces the `useGameState` hook and the game reducer. The reducer starts with just the `SELECT_CELL` action but will grow as subsequent stories add more actions. The hook initializes with a hardcoded puzzle for now.

Highlighting has three visual states:
1. **Selected** — the clicked cell (strongest highlight, e.g., `bg-blue-300`)
2. **Peer highlight** — same row/col/box (medium highlight, e.g., `bg-blue-100`)
3. **Same value** — cells with the same number as the selected cell (e.g., `bg-blue-200`)

Use `getAllPeers()` from board-utils to compute peer cells.

// Game reducer pattern
export type GameAction =
  | { type: 'SELECT_CELL'; position: Position }
  // ... more actions added by later stories

function gameReducer(state: GameState, action: GameAction): GameState {
  switch (action.type) {
    case 'SELECT_CELL':
      return { ...state, selectedCell: action.position };
    // ...
  }
}

export function useGameState(initialPuzzle: CellValue[][], solution: CellValue[][]) {
  return useReducer(gameReducer, createInitialState(initialPuzzle, solution));
}
